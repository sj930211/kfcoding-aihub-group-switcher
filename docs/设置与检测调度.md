- 各类证据独立校验：模型卡片有评价时间时使用该时间及显式有效期，非法时间不能借组时间；匹配模型检测有有效期时使用自身有效期，缺省才回退组时间；最新探测样本用样本时间，整体成功率/延迟用组时间。FluxionAI 成功率只接受有效数值或非空数值字符串，空串/空白/布尔值为未知，数值0不丢弃。
- 切换观察期间同样不把未知当故障；发生明确故障后，按当前三种策略选健康候选，不能为了回原组覆盖策略。原组恢复不自动回切。默认 strategy 保留原观察/优先回滚行为。
- AIHub `group_models` 存在时为实际模型范围（含显式空列表）；旧接口缺失时回退卡片/旧健康别名。模型检测必须精确匹配目标，仍是健康证据，无新数值权重。

## 契约及验收

- S1 两个可单独配置的周期：故障检测默认30秒、择优默认300秒。旧pollSeconds保留为故障间隔，已有值不覆盖；旧配置缺少strategySeconds时补300秒。单次请求不重叠、周期同到合并，每次完成后开始下一个相应周期，不追赶补跑。
- S2 故障周期检查当前业务组及切换后回滚观察，不增加正常择优确认、不启动新图片任务、不重启保持期。正常择优确认只按择优轮次累计，保持期仍按实际时间计算，预评价窗口使用择优间隔。若已有正常决策确认完成且图片通过，故障检查可在全新监控请求后核对候选并完成该决策。
- S3 当前分组故障时立即刷新完整候选及账号分组倍率，再按最新健康状态恢复，不等待择优周期、不评价图片；仍遵守健康隔离及用户名单。健康请求每轮读取新监控数据；平台接口返回全量监控时也只推进本轮职责。普通健康轮次复用分组/倍率目录，不更新其他分组列表及策略推荐；当前组指标可刷新。消费用量不随每个健康轮次重复刷新。
- S4 评分完成仅催促健康检查，不提前下一次择优周期；页面重新可见也只催促健康检查。模型/密钥等设置保存取消旧决策，普通保存使择优等待完整配置间隔，明确启用自动切换时允许立即首轮检查。选择评分设置不会直接测试模型。
- S5 设置为自动切换/检测保护/图片评价/消费提醒/界面更新五分类；非AIHub隐藏图片分类。检测间隔和切换保护直接展示，健康判定、隔离详情、备用评分线路/图片任务、评分规则与本页评价按需展开。保留所有已有配置及操作，不持久化评分、不改变评分密钥备用换组和恢复规则。

### AIHub 业务平台范围 v2（本地 1.0.0）

监控页的平台选择是持久化的业务范围：全部平台 / OpenAI / DeepSeek / Zhipu GLM / Kimi / Grok / 未知平台。默认全部，旧配置默认全部；依据站点 platform 元数据，缺失或未知归入未知，不根据名称猜测。自动择优、仅故障转移、立即检查和策略推荐，先取“业务平台＋同组支持全部目标模型＋生效白/黑名单”的交集，再详细计算指标。多平台同名组按真实组 ID 区分。

当前业务组即使被排除，仍检查健康；范围变化不算故障，健康或没有明确故障时保持当前组。故障恢复与回滚只能选交集内健康组，无目标则保持并提示，不跨平台兜底。健康周期只深入评估当前业务组，确需恢复或兑现已确认准入时才加载范围内候选；不增加择优确认或新图片评分。公共 providers/series 仍为批量接口，减少的是本地详细计算和下游图片准入，不承诺缩小服务响应。

改变业务范围会保存配置、清除旧候选/推荐和确认、使旧自动图片任务失效；只保存时不立即检查、评分或切组，下次计划检查或手动“立即检查”生效。等待切换锁期间仍核对设置快照，拒绝旧范围写入。旧评分请求的结束/恢复仍遵循原路由保护。
