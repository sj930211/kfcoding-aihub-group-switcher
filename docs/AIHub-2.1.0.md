# AIHub 分组工作台 2.1.0

本地版本2.1.0，设计 `AIHUB-DECISION-2.1-v1` 已于2026-11-03获确认。未提交、推送、发布或安装；用户尚未验收。本说明覆盖2.0.0中的评分、模型身份和切换观察规则，其余监控范围、精确模型检测、手动风险确认、AIHub-only和图片评价删除行为继续沿用。

## 权重和本地预览

设置 → 自动切换提供成功率/缓存命中/TPS/低倍率四权重，默认40/30/20/10。每项0–100整数，合计必须100%；允许单项0，全0与非法总和拒绝保存。损坏的已存权重整套恢复默认并提示。最小质量收益默认5分，可设0–100；即使设0，同分也保持当前。

编辑为草稿，恢复默认只改草稿；显式保存后下次检查生效。预览与实际评分使用同一函数、同一当前快照、同模型和同一准入；缺当前组完整数据不生成假推荐。保存取消旧决策与待确认，不联网、不调用模型、不立即切组。

预览分别展示已保存/草稿的排名优胜、分项贡献和条件性决策，采用收益门槛、运行模式及密钥模型权限；排名不代表即将执行切换。保存后的列表分数、排序和详情使用新权重本地重算，实际自动决策仍等待后续检查。

## 固定标尺与样本保守系数

先通过模型检测、权限、范围、倍率、1h新鲜度、成功率、模型/缓存样本等硬门槛，再评分。权重0不关闭任何门槛，缺项不补0、不按剩余权重归一化。

设p为成功率百分数，c为缓存命中百分数，t为tokens/s，r为账户名义倍率，n为同模型样本，m为缓存usage_records：

```text
U成功 = clamp(100 × (p − 最低成功率) / max(100 − 最低成功率, 5), 0, 100)
U缓存 = c
UTPS  = 100 × t / (t + 100)
U倍率 = 100 / (1 + r)
q模型 = n / (n + 100)
q缓存 = m / (m + 100)
综合分 = w成功 × U成功 × q模型 + w缓存 × U缓存 × q缓存
       + wTPS × UTPS × q模型 + w倍率 × U倍率
```

w为百分比除100。固定工程尺度为TPS100、样本100、倍率1、成功余量分母至少5个百分点。样本系数不是统计置信度，综合分也不是服务成功概率；会偏向大样本组，尚无真实历史回放证明这些尺度最优。最低成功率100时成功余量为0，不重新分配权重。

加入/移除第三组不影响原分数。正常切换要求当前及目标均有完整合格数据、同绑定模型，目标严格高于当前且至少达到收益门槛，再累计新证据确认并满足保持期。当前未知、数据缺失、仅受配置限制均保持，不借故障恢复绕过。

## 每个密钥一个决策模型

`tokenModels`只存内部密钥ID→精确模型名，不存凭证，不改变实际业务请求model。旧单启用模型自动绑定已选密钥；旧多模型不猜用途，未绑定密钥暂停并提示，其他已绑定密钥继续。用户主动清空绑定不会再次自动迁移。

全局模型仍用于目录/浏览；取消勾选不替换绑定，相关密钥暂停。组最新检测详情必须精确等于绑定模型；详情换到其他模型时暂停，不复用历史通过结果。密钥模型权限也要允许该模型。旧多模型观察与隔离保留为历史，不套用到新的单模型身份。

## 正常确认与切换观察

正常确认以当前及目标的指标窗口、关键指标/样本变化为证据，同一证据只计一次。全局generated_at、请求时间、缓存refreshed_at、重复立即检查、单纯检测时间更新均不增加择优确认。目标、模型、配置、收益条件变化会取消旧确认；健康周期不累计正常择优。

切换观察记录目标准确组ID、绑定模型、switchAt、剩余次数及已用证据。只接受同组同模型在切换后发布的合格健康证据：检测完成时间（含启用阶段完成时间）或明确的模型指标窗口结束时间。缓存刷新和全局时间不计观察。每份证据最多计一次；旧记录缺少switchAt时重新开始未验证观察，不能沿用旧计数。

没有新证据显示“等待新健康证据”；10分钟后标为“观察未验证”，保持暂停正常择优，继续健康轮询、明确故障恢复和后续观察。不因超时宣布成功。观察通过只表示平台分组证据通过，并非该密钥业务请求已实测成功。

## 故障恢复和应急层

只有当前绑定模型的新鲜明确检测失败或合格的同模型1h低成功率才能触发恢复。先选正常完整候选，使用相同固定分数；无完整候选时才允许只缺缓存/TPS排名数据的应急组。

应急目标仍须在监控范围、账号可选、准确ID、名单及倍率限制内、未隔离，支持绑定模型；最新同模型检测明确通过，v2/1h成功率新鲜有效且达到门槛，模型样本足够。成功率/检测/样本未知或模型不匹配一律拒绝。应急不生成普通质量分，依次按成功效用×模型样本系数、原始成功率、模型样本、低倍率、组ID排序。

恢复绕过正常收益、择优确认和保持期，保留写前冲突检查、锁、写后校验和观察。回滚先选择完整/应急层，再在该层优先准确原组ID；不为了回原组降层、猜同名组或绕过范围/安全门槛。无安全目标保持并告警。

两种自动模式的回滚均遵循该原ID优先规则，回滚目标也建立新的观察；原失败组继续隔离，不能为了回原组忽略安全条件。

## 上游故障时效限制

30秒是轮询间隔，故障发现取决于上游证据发布，不能保证30秒发现故障。短时健康卡仅展示状态、样本、评估和过期时间；其字段语义尚未核实，不接入自动故障。插件不自行调用付费模型补数据。

验证仅来自源码VM、本地模拟IO与localhost真实浏览器操作；这些不等于真实网关、付费推理或线上持续运行验证。执行证据见本批唯一任务记录。
