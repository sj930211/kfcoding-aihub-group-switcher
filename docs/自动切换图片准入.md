# 自动切换图片准入

## v1.0.0 兼容说明

新增的“仅故障转移”模式在正常情况下不进行自动择优，因此不启动新图片评价，也不完成模式变更前的旧择优决策。明确故障恢复仍跳过图片准入，按配置策略选择健康目标；手动指定分组仍跳过准入。默认“正常择优与恢复”沿用本规格全部评分、请求预算、固定模型、备用评分密钥分组和先恢复原分组再业务切换的约束。搜索仅过滤选择器，不发起测试或推理；既有诊断保留。本次版本仅将已确认的本地实现标记为稳定首版，证据见 `任务/2026-10-23-v022/执行记录.md`，历史实测不计为本次验证。

状态：SELF_VERIFIED / PASS。图片评分格式解析修复已完成本地验证；版本及远端交付状态以对应Git标签和GitHub Release为准。

## 行为契约

检测与择优周期的后续拆分及设置重排见[设置与检测调度](设置与检测调度.md)，其中明确健康周期不累计择优确认、不启动新图片任务；其他评分/恢复边界继续沿用本文。

- R1 图片分不参与策略、健康分或列表排序。正常择优须图片分严格大于门槛（默认80），且证据充分；手动指定目标跳过图片检查。“立即策略切换”保留主动等待准入的行为。
- R2 正常自动择优改成后台预评价。候选累计达到`max(1, 确认次数-1)`，且当前保持期剩余不超过一个择优周期时启动。较长保持期、早期确认、当前即推荐、单纯刷新目录不调用评价模型。启动自动切换即授权符合上述时机的计费评价。
- R3 轮询不等待评分；评分完成不会直接业务切组。通过后，须等待评分结束后才发起的新一轮健康检查，再核对策略候选、保持期、连续确认、设置、图片目录、外部密钥改组及评价有效性，才切换。
- R4 当前业务组不可用时优先恢复服务，回滚也跳过图片评价。先取消后台任务并等待评分密钥恢复、校验，再按健康策略切组。故障恢复忽略图片隔离，继续遵守健康隔离与用户黑白名单。
- R5 无图、图片读取失败、明确无法识别、证据不足、有效低分进入故障隔离，按配置分钟到期；不写用户黑名单。隔离记录标注图片/健康及原因。旧无类型记录按健康隔离处理，两类记录可以共存。评分服务故障、超时、认证/协议异常或请求预算耗尽，不隔离未被判为图片不合格的业务组。
- R6 同一次待切换决策共享最多10次模型请求（含失败与备用线路），跨普通轮询不重置。拒绝候选后下一候选仍使用该预算；同一决策可共享相同候选评价。决策结束、设置或目录改变、停止或明确切换时取消旧决策；以后独立决策重新读图和评价。不持久化评分、不读取历史缓存；本页展示记录不能用于下次准入。
- R7 评分服务不可用时仅改变评分密钥分组，不改变评价模型。按当前/备用1/备用2依次尝试，仅使用已配置且账号可选组。同一决策跳过已失败评分线路；全部不可用时暂停本次择优，普通轮询不付费重试。调整设置或关闭后重新启用自动切换可开始新决策，故障恢复仍可执行。
- R8 评分切组保持事务式恢复与Web Locks互斥。写前/后及恢复前检查实际组，不覆盖已观察到的外部改组；丢失写响应也检查可能已成功的切组。评分密钥兼作业务密钥时，监控使用临时切组前的逻辑分组；恢复后才业务写入。恢复无法确认时废弃分数、暂停全部切换，要求检查评分密钥并刷新页面。
- R9 候选、原业务组、设置或图片变更时取消相应过期任务，晚到结果不能切组或隔离。取消后台任务只中止其拥有的请求，不能误停独立手动评价。取消后仍完成必要的原组恢复。
- R10 界面显示评价中/待评价/服务异常/未通过及本页分数，详细依据保留悬停与图片详情；评分设置简述正常择优/故障恢复，计算时机与完整规则收进折叠说明。单张测试仅当前评分分组1次，不切组；手动批量保留有序备用时串行、无备用时最多2并发。
