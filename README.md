# KFCoding / AIHub 智能低倍率分组切换

油猴脚本支持 `kfcoding.codes` 和 `aihub.top`，会读取当前站点的分组倍率、账号可选范围和性能监测数据，把选中的一个或多个 API 密钥切换到满足可用性阈值的最低倍率分组。

## 安装

1. 在浏览器安装 Tampermonkey。
2. 点击[安装脚本](https://raw.githubusercontent.com/sj930211/kfcoding-aihub-group-switcher/main/kfcoding-group-switcher.user.js)，由 Tampermonkey 确认安装。
3. 登录 `https://kfcoding.codes/` 或 `https://aihub.top/usage`，页面右下角会出现对应站点的分组监控。
4. 需要切换时勾选一个或多个 API 密钥。KFCoding 还需要选择目标模型；AIHub 使用站点公共渠道监测，不提供模型选择。
5. 调整阈值后开启 `自动切换`，点击 `保存`。

面板会展示当前账号的本日消费、请求次数和 Token 总量，并在启动、每次分组检查和手动刷新时更新。`立即检查`只刷新判定结果；AIHub 即使未选择 API 密钥也会显示分组状态。`立即切换`会实时检查全部已选密钥，并将需要调整的密钥直接切到最低可用倍率分组；它忽略自动开关、连续确认次数和切换冷却，但不会绕过倍率上限、整体成功率、最近一次监测、指标时效、延迟、密钥状态、模型限制和账号可选范围等条件。

检查完成后，可以在`手动选择分组`中指定一个当前可用分组，再点击`手动切换`。脚本会重新获取定价、性能指标、账号分组和全部已选 API 密钥状态，确认该分组仍然可用后逐个切换；它不会改为更低倍率的其他分组。当前不可用的分组仍会显示在列表中，但无法选择；已经处于目标分组的密钥不会重复提交修改请求。

脚本只保存所选 API 密钥的内部 ID 列表，不保存或显示完整密钥。旧版 KFCoding 单密钥配置会自动迁移。两个站点分别保存配置、日志、拖动位置和冷却记录，互不覆盖。

面板事件会持久保存最近 10 条，刷新页面或重新打开浏览器后仍可查看；新增事件会自动淘汰最早的记录。

收起后的 `KF` 或 `AH` 按钮可以直接拖动，展开后的面板可以按住标题栏拖动。按钮和面板的位置分别保存，刷新页面后仍会恢复；窗口尺寸变化时会自动调整，避免控件停留在屏幕外。

读取接口单次超时为 25 秒，遇到超时、网络错误、限流或临时服务端错误时最多请求 3 次。同一路径的并发读取会自动合并。修改 API 密钥的请求不会自动重试，避免重复提交。

## 默认判定

候选分组必须同时满足：

- KFCoding 的目标模型已启用该分组；AIHub 的公共监测包含该分组。
- 当前账号可以为 API 密钥选择该分组。
- 分组倍率可确定。
- 分组倍率不超过配置的最大倍率；默认 `0` 表示不限制。
- 24 小时总成功率不低于 95%。
- 最近一次监测成功率不低于 95%；只判断时间最新的数据点，更早的异常柱不影响当前判定。
- 最新指标不超过 180 分钟，延迟不超过 120 秒。

满足条件后按倍率升序选择。每个密钥独立计算连续确认和切换冷却：更便宜的分组需要连续确认 2 次并遵守 10 分钟冷却；某个密钥的当前分组失效时，该密钥不等待冷却，立即回退到可用分组。单个密钥读取、校验或切换失败不会阻断其他已选密钥。

最大倍率是统一的硬性限制，会同时约束自动切换、立即切换和手动切换。超过上限的分组会标记为不可用，不能通过手动选择绕过。

## 运行限制

- 油猴脚本只有在对应站点至少有一个页面打开时运行。后台标签页可能被浏览器节流，30 秒轮询不等于严格的实时任务调度。
- 可用性来自供应商公开的历史性能指标，能降低切到故障分组的概率，但无法保证下一次请求一定成功。
- 如果所有候选都不满足阈值，脚本保持现有分组不变并显示原因。
- 今日用量按浏览器所在时区的本地自然日统计；KFCoding 使用站点公开的配额换算设置展示消费金额。

### AIHub 说明

- 倍率优先采用当前账号的分组倍率，其次使用可选分组倍率和公共监测倍率。
- 可用性读取 `/api/v1/public/monitor/summary` 和 `/api/v1/public/monitor/series/{range}`，近期状态只采用时间最新的一个监测点。
- AIHub 公共监测没有模型字段，因此只能判断分组级可用性，不能声称某个指定模型一定可用。
- 密钥分组更新沿用站点前端接口，只提交 `group_id`，成功后重新读取密钥详情确认结果。
