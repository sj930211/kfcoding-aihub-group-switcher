# KFCoding / AIHub / ooioo / FluxionAI 智能低倍率分组切换

油猴脚本支持 `kfcoding.codes`、`aihub.top`、`ooioo.work` 和 `fluxionai.space`，会读取当前站点的分组倍率、账号可选范围和性能监测数据，把选中的一个或多个 API 密钥切换到满足可用性阈值的低倍率分组。

## 安装

1. 在浏览器安装 Tampermonkey。
2. 点击[安装脚本](https://raw.githubusercontent.com/sj930211/kfcoding-aihub-group-switcher/main/kfcoding-group-switcher.user.js)，由 Tampermonkey 确认安装。
3. 登录 `https://kfcoding.codes/`、`https://aihub.top/usage`、`https://ooioo.work/` 或 `https://fluxionai.space/`，页面右下角会出现对应站点的分组监控。
4. 从下拉选择器中勾选一个或多个 API 密钥，并选择一个或多个目标模型。AIHub 的模型多选列表来自站点公共监测当前返回的 Sol、Terra、Luna、Astra 等模型状态。
5. 按需设置分组白名单或黑名单，调整阈值后开启 `自动切换`。所有设置在变更后会自动保存。

## 源码与发布文件

仓库采用“多文件源码、单文件发布”的结构。`src/` 按职责保存站点配置、供应商适配、候选选择、统计、运行时状态和界面代码；`scripts/build.mjs` 将这些模块按固定顺序组装为根目录的 `kfcoding-group-switcher.user.js`。油猴仍然只需要安装这个单文件，不使用运行时 `@require` 网络依赖。

本地修改源码后运行：

```bash
npm run build
npm test
```

`src/` 是唯一源码，根目录的 `kfcoding-group-switcher.user.js` 是生成产物，不应直接编辑。构建会校验油猴 metadata 版本与面板运行时版本一致。

面板采用统一窄版的运维控制台布局，并划分为`监控 / 统计 / 诊断 / 设置`四个内部工作区：监控页集中显示当前路由、今日用量、常用操作和分组状态；统计页查看账户每日趋势、所有当前密钥的使用度和账单对账状态；诊断页保留逐密钥结果和最近事件；设置页集中管理自动切换策略、保护参数、脚本更新及`跟随系统 / 浅色 / 深色`主题。毛玻璃透明度可在设置页通过滑杆实时调整并自动保存。所有设置修改都会自动保存。界面也支持键盘方向键切换工作区，以及降低动态效果、降低透明度和高对比度等系统辅助偏好。

脚本会通过 `@updateURL` 接收 GitHub 上的新版本。更新检查使用独立定时器，不依赖自动切换开关：脚本启动时会静默检查一次，之后每 5 分钟检查一次。发现新版本后会发送一次油猴通知，在顶部版本号旁显示 `NEW`，并在设置页提供更新按钮；同一版本不会因刷新页面或同时打开两个供应商网站而重复通知。需要立即确认时，可以在设置页底部点击`检查更新`，或从 Tampermonkey 菜单选择`检查脚本更新`。更新检查失败不会阻断分组监控或自动切换，也不会上传任何 API 密钥或账号数据。

面板会展示当前账号余额、本日消费、请求次数和 Token 总量，并在启动和每次分组检查时更新。KFCoding 与 ooioo 余额使用各自站点的配额货币换算设置，AIHub 与 FluxionAI 读取当前账号余额；Token 达到百万后使用 `M`，达到一亿后使用“亿”，悬停可查看精确数值。选择多个目标模型时，只有同时支持并通过全部目标模型门槛的共同分组才会参与自动推荐；列表用最低成功率、最慢首字/输出延迟、最低缓存命中率和最高倍率作为保守展示与评分，避免一个健康模型掩盖另一个异常模型。分组列表会展示所有评估出的渠道，不再截断固定数量。倍率列按站点显示路由倍率；AIHub 优先显示当前账号实际可路由倍率，并在它与页面公开倍率不同时同时标出页面倍率，再显示平台返回的 1M 真实输入价格和预测倍率。`rate_multiplier`、账号分组倍率、`effective_input_price_per_million_1h` 和 `effective_multiplier` 是不同字段，不能拿页面上的单一倍率直接与插件的账号路由倍率比较；AIHub 在 `effective_multiplier_ready=true` 时直接使用公共监测返回的 `effective_multiplier`，不再根据缓存命中率自行换算。统计窗口未就绪、样本不足以及其他站点未提供该字段时显示 `≈-`，悬停可查看原因。分组状态还会展示首字延迟、完整输出耗时和缓存命中率。KFCoding 与 ooioo 直接使用性能接口的平均首字延迟与平均完整输出耗时；AIHub 首字列按页面用户速度口径优先使用有有效样本的“最快95%平均”并按毫秒显示，缺失时依次回退到 P90 和探针，并在悬停提示中标明来源；如果页面查看的是探针/检测延迟，数值不同是指标口径不同而不是单位换算错误。AIHub 的完整输出耗时按输出 Token 数除以 Token/s 计算；FluxionAI 将渠道监控中的“对话延迟”作为完整输出耗时。FluxionAI 当前未提供首字延迟和缓存命中率，因此对应列显示 `-`，也不会把缺失的首字延迟当作硬性失败。缓存命中率不作为可用性的硬门槛；它会参与稳定优先和均衡推荐的健康评分。平台预测倍率来自最近运行窗口，能比固定缓存基线更完整地反映当前计费结构，但仍不等于最终账单。`立即检查`始终先刷新余额与今日用量，并同时刷新 API 密钥列表、模型和分组状态；即使尚未选择模型或 API 密钥，余额与今日用量也会更新。AIHub 和 FluxionAI 的普通立即检查不要求先选择 API 密钥，但都需要至少选择一个目标模型。`切到策略推荐`会实时检查全部已选密钥，并按照当前策略切换；它忽略自动开关、连续确认次数和切换后保持，但仍遵守当前生效的分组名单、倍率上限、全部目标模型状态和健康门槛。

统计页目前只在 AIHub 启用真实历史数据，支持`实际消费 / 请求数 / Token`三种指标和`今天 / 最近 7 / 14 / 30 天`，默认显示今天的实际消费。选择“今天”时，账户趋势只展示已经完成的本地小时区间，例如 11:20 显示 `01:00–11:00`，并在用户停留于可见的“统计 / 今天”页面时每 5 分钟刷新；离开页面、切换日期范围或页面进入后台后停止该定时刷新。选择其他范围时按自然日展示。鼠标悬停或键盘聚焦趋势点可查看该点的日期/小时、实际消费、请求数和 Token 详情。消费金额严格使用`actual_cost`并明确标注 USD；每个密钥的柱状图逐个读取站点真实日明细，使用最多 3 个并发请求，并复用已加载的当前密钥列表，避免重复分页请求。今天的小时趋势仅用于绘图，对账另取同一天的账户日汇总，从而与密钥日累计保持相同窗口；日汇总不可用时显示“待对账”，不会用部分小时总量误报异常。缺失的自然日或已完成小时补 0，但接口失败或字段缺失不会伪装成 0。统计刷新先显示分阶段 loading 和进度；只有全部当前密钥读取成功且时间窗口一致时才显示精确覆盖率和`其他/已删除密钥`差额；单个密钥失败会标记为“部分数据”，同窗口内密钥合计超过账户总量才显示“对账异常”，不会把覆盖率静默截断到 100%。KFCoding、ooioo 和 FluxionAI 尚未完成对应历史账单接口核验，因此统计页明确显示不可用，不会套用 AIHub 字段或平均分摊账户消费。

分组过滤使用互斥的`白名单 / 黑名单`模式下拉和分组多选下拉。两种模式分别保存自己的名单，切换模式不会覆盖另一份；任何时刻只应用当前模式。白名单非空时只允许名单内分组，黑名单非空时排除名单内分组；当前名单留空表示不限制。旧版共用输入框的数据会按升级前启用的模式迁移到对应名单，更早版本的“允许分组”会迁移到白名单。

检查完成后，点击与`自动切换`并列的`手动切换`，弹窗会开放本次检查得到的全部分组，并在每个选项后显示倍率、完整状态和多模型异常详情。分组选项由插件自行绘制并在弹窗内滚动，不依赖 macOS/Windows 绘制方式不同的原生长下拉列表；其他仍使用原生下拉的策略、名单模式和主题选项也固定了浅色/深色文字与背景。人工选择可以覆盖黑白名单、倍率上限和性能门槛，脚本会重新获取分组与密钥状态后尝试逐个切换；账号无权选择的分组仍可能被站点接口拒绝，并会记录到密钥结果和事件中。已经处于目标分组的密钥不会重复提交修改请求。

分组选择提供三种模式：`省钱优先`在 AIHub 优先按已就绪的平台预测倍率从低到高排序，未就绪候选排在已就绪候选之后；如果所有可用候选都没有平台预测倍率，才按标称倍率兜底。其他站点未提供平台预测倍率时同样按标称倍率排序。`稳定优先`综合近期成功率、整体成功率、首字延迟、完整输出耗时和缓存命中率；`均衡推荐`按健康分 70% 与相对价格 30% 综合排序，其中 AIHub 的价格分同样采用已就绪的平台预测倍率，不会把标称更低但预测更贵的分组误判为便宜。存在已就绪预测时，预测未就绪的 AIHub 分组不会获得虚构的低价优势；全部未就绪时才按标称倍率兜底。所有模式都只从满足当前自动判定门槛的分组中推荐，切换确认、切换后保持和回滚保护保持不变。

消费保护可以设置每日消费上限。保护计数达到 80% 时显示橙色并通知一次，达到 100% 时显示红色并再次通知；它只负责提醒，不会暂停自动切换、阻止立即检查或修改任何任务。点击重置会把站点当前返回的今日消费记录为新基线，之后只统计新增消费；本地日期变化时基线和通知状态会自动归零，供应商账单本身不会被修改。

每次成功切换后，脚本默认保持当前渠道 10 分钟。保持期间仍按轮询周期检查全部渠道和目标模型：当前渠道仍可用时不追逐其他推荐渠道，任一基础健康门槛或已启用的模型检测门槛失败时立即绕过保持时间切换；保持期结束后恢复当前策略择优，如果当前渠道仍是最优则开始下一保持周期。旧版“切换冷却”设置会自动迁移为“切换后保持”。脚本还会继续观察目标分组 2 次；观察失败时优先回到切换前的分组，原分组也不可用时按当前策略改用其他可用分组。发生健康故障的目标分组会按当前目标模型组合临时拉黑 60 分钟，避免多个密钥或后续轮询立即切回；调整模型组合后不会错误沿用另一组合的保持、观察或隔离状态。分组状态列表会显示“临时拉黑”，事件中会记录回滚。高级参数可以调整保持时间、观察次数和拉黑时间，将保持时间或观察次数设为 `0` 可分别关闭对应保护。旧版本的单目标模型配置会自动迁移为单元素模型列表，行为保持不变；旧版本的“最大延迟”会自动迁移为最大首字延迟；旧版按秒/Token 保存的输出延迟阈值不会套用到新版完整输出耗时，避免单位变化造成误判。

脚本只保存所选 API 密钥的内部 ID 列表，不保存或显示完整密钥。旧版 KFCoding 单密钥配置会自动迁移。四个站点分别保存配置、日志、拖动位置和保持记录，互不覆盖。

KFCoding 和 ooioo 的新版账户接口使用短期 access token。脚本会通过当前站点的 HttpOnly 登录会话在运行内存中获取并刷新 token，遇到 401 时只刷新并重试一次；token 不会写入油猴存储、`localStorage` 或事件日志。会话失效时，面板会明确提示对应站点需要重新登录。

AIHub 和 FluxionAI 复用页面当前的 Bearer 登录状态。脚本每次请求只读取站点当前 token，不会把 access token、refresh token 或完整 API 密钥复制到油猴存储和事件日志；登录状态失效时需要先在对应站点重新登录。

面板事件会持久保存最近 10 条，刷新页面或重新打开浏览器后仍可查看；新增事件会自动淘汰最早的记录。

收起后的 `KF`、`AH`、`OO` 或 `FX` 按钮可以直接拖动，展开后的面板可以按住标题栏拖动。按钮和面板的位置分别保存，刷新页面后仍会恢复；窗口尺寸变化时会自动调整，避免控件停留在屏幕外。

读取接口单次超时为 25 秒，遇到超时、网络错误、限流或临时服务端错误时最多请求 3 次。同一路径的并发读取会自动合并。修改 API 密钥的请求不会自动重试，避免重复提交。

## 默认判定

候选分组必须同时满足：

- KFCoding 或 ooioo 的全部目标模型均已启用该分组；AIHub 的公共监测包含该分组且 `model_health` 对全部目标模型都提供可接受证据；FluxionAI 的可选分组支持全部目标模型，并且每个模型都能匹配到对应渠道监控。
- 当前账号可以为 API 密钥选择该分组。
- 分组倍率可确定。
- 分组倍率不超过配置的最大倍率；默认 `0` 表示不限制。
- 总成功率不低于 95%。KFCoding 与 ooioo 使用所选监测窗口；当前 AIHub v2 契约明确使用平台返回的 1 小时整体成功率，设置中的趋势窗口只控制探测序列和旧接口回退；FluxionAI 使用站点提供的 7 天可用率。
- 最近一次监测成功率不低于 95%；只判断时间最新的数据点，更早的异常柱不影响当前判定。
- 最新指标不超过 180 分钟；站点提供首字延迟时默认不得超过 120 秒，完整输出耗时默认不限制。FluxionAI 未提供首字延迟，因此只展示和判断其对话总延迟。

满足条件后按当前选择模式排序，升级后的默认模式为`省钱优先`；AIHub 直接采用公共监测返回且已就绪的 `effective_multiplier`，不再运行旧版 97% 缓存基线公式。只有所有可用候选的预测倍率都未就绪时，省钱模式才按标称倍率兜底。每个密钥独立计算连续确认、切换后保持、切换观察和故障隔离：目标分组需要连续确认 2 次；切换后默认保持 10 分钟并观察 2 次，健康故障分组默认拉黑 60 分钟。保持期不会停止检测；某个密钥的当前分组失效时立即回退到可用分组。单个密钥读取、校验、切换或回滚失败不会阻断其他已选密钥。

最大倍率会约束自动切换和`切到策略推荐`。超过上限的分组会标记原因，但仍可在手动切换中由用户明确选择。

## 运行限制

- 油猴脚本只有在对应站点至少有一个页面打开时运行。后台标签页可能被浏览器节流，30 秒轮询不等于严格的实时任务调度。
- 可用性来自供应商公开的历史性能指标，能降低切到故障分组的概率，但无法保证下一次请求一定成功。
- 自动回滚同样依据供应商的分组监控数据，不会使用 API 密钥主动发送可能产生费用的模型请求，因此无法捕获监控尚未反映的单次业务请求失败。
- 如果所有候选都不满足阈值，脚本保持现有分组不变并显示原因。
- 今日用量按浏览器所在时区的本地自然日统计；KFCoding 与 ooioo 使用各自站点公开的配额换算设置展示消费金额，AIHub 与 FluxionAI 使用站点返回的实际消费金额。

### ooioo 说明

- 模型、分组倍率和模型可用分组读取 `/api/pricing`；整体和近期性能读取 `/api/perf-metrics`，近期状态只使用时间最新的数据点。
- 当前账号可选分组、API 密钥列表/详情、本日用量和余额分别读取 `/api/user/self/groups`、`/api/token/`、`/api/data/self` 与 `/api/user/self`。
- 密钥更新沿用站点前端的 `PUT /api/token/` 负载，并在更新后重新读取详情确认分组。修改请求不会自动重试。
- ooioo 使用独立的 `ooioo-group-switcher` 存储前缀，不会继承或覆盖 KFCoding、AIHub 的密钥选择、黑白名单、保持或故障隔离状态。

### FluxionAI 说明

- 账号余额、API 密钥、可选分组、账号倍率和今日用量分别读取 `/api/v1/auth/me`、`/api/v1/keys`、`/api/v1/groups/available`、`/api/v1/groups/rates` 与 `/api/v1/usage/stats`。
- 可用性读取 `/api/v1/channel-monitors`。整体成功率使用站点返回的 `availability_7d`，近期状态只采用 `checked_at` 时间最新的一个监测点，不依赖数组原始顺序。
- 站点监控名称与实际可选分组名称并不完全相同。脚本会同时核对目标模型、平台和标准化分组名；无法可靠匹配的分组标记为“无性能数据”，不会参与自动切换。
- 模型多选列表只展示同时存在可选分组和渠道监测的模型。未被站点监测的模型不会借用同分组其他模型的状态来声称可用。
- 倍率优先采用账号专属倍率，其次采用当前有效的促销倍率，再回退到基础倍率；处于站点配置的高峰时段时会叠加高峰倍率。
- FluxionAI 当前渠道监控提供对话总延迟和端点 PING，但未提供首字延迟、输出 Token/s 或缓存命中率。脚本把对话总延迟显示为完整输出耗时，其余缺失指标显示 `-`。
- 密钥更新沿用站点前端的 `PUT /api/v1/keys/{id}`，只提交 `group_id`，成功后重新读取密钥详情确认结果。修改请求不会自动重试。
- FluxionAI 使用独立的 `fluxionai-group-switcher` 存储前缀，不会继承或覆盖其他三个站点的密钥选择、黑白名单、保持或故障隔离状态。

### AIHub 说明

- 倍率优先采用当前账号的分组倍率，其次使用可选分组倍率和公共监测倍率；列表会明确标识这是账号路由倍率还是页面倍率，并在二者不同的情况下同时展示，避免把账号专属价格和公共页面价格混为一谈。
- 可用性优先读取 `/api/v2/public/providers` 和 `/api/v2/public/providers/series`，v2 汇总不可用时回退到同路径的 v1 版本，二者均不可用时再回退到 `/api/v1/public/monitor/summary` 和 `/api/v1/public/monitor/series/{range}`。监控页与模型目录共用这条回退链。序列接口临时不可用时保留同版本的有效汇总，不混入其他版本。v2 的整体成功率固定采用 `1h`；v1/legacy 优先使用设置所选窗口，其次为 `24h`，二者均缺失时采用明确标注的 `1h`。已有窗口值无效时保持未知，不通过回退到更好的统计值放行。近期状态只采用时间最新的一个监测点；仅当分组的 `probe_model` 与目标模型相同时才使用该柱状图，否则使用目标模型自己的 `model_health`，避免 Luna 等其他模型的故障误判 Sol。
- 首字延迟优先读取公共监测的 `runtime_trimmed_avg_ttft_ms`（最快 95% 用户平均），无有效样本时回退到 `runtime_p90_ttft_ms`，再回退到 `probe_e2e_ttft_ms`；列表按页面同口径显示毫秒，并在悬停提示中标明来源。缓存命中率读取公共监测的 `cacheHitRate`；完整输出耗时使用 `outputTokens / outputTokensPerSecond` 计算。
- 平台预测倍率读取 `effective_multiplier`，并且只在 `effective_multiplier_ready=true`、数值有效时用于列表展示和省钱排序；`effective_input_price_per_million_1h` 作为悬停详情。未就绪时读取 `effective_multiplier_reason` 展示“统计窗口未就绪”或“样本不足”，不再根据缓存率自行推算。
- 模型多选列表从公共监测的 `model_health` 键生成，并把 `astra` 映射为 `gpt-6-astra`，Sol、Terra、Luna 的既有名称保持不变。每个目标模型状态为 `healthy` 时允许继续判定，任一模型为 `failed` 都会显示“目标模型不可用”。设置中的“模型检测参与切换”默认关闭：关闭时 `model_detection` 只显示警告，不会为 `stale` 状态背书或改变渠道资格；开启后，与已选目标模型匹配的 `model_detection.status` 为 `passed` 即可作为当前模型证据，不再要求新接口已省略的有效期和完成标志；若接口显式返回已过期、未完成或未全部通过，仍会立即判为不可用并绕过保持时间切换。AIHub 当前每个渠道只提供一条检测记录，因此没有匹配检测记录的其他已选模型继续由 `model_health` 和基础指标判定，不会因缺少逐模型检测记录被误杀。
- 密钥分组更新沿用站点前端接口，只提交 `group_id`，成功后重新读取密钥详情确认结果。
- 统计页的账户日趋势读取`GET /api/v1/usage/dashboard/trend`，按密钥日明细读取`GET /api/v1/user/api-keys/{id}/usage/daily`；两类请求共用浏览器当前时区和同一组自然日边界。今天按已完成小时展示并每 5 分钟刷新，昨天按前一自然日完整 24 小时展示且不自动刷新。批量密钥用量接口只提供今日与默认最近 30 天消费，缺少统一范围、请求数和 Token，因此不作为统计页数据源。
- 统计刷新只发送读取请求，不会调用模型、修改密钥分组或保存完整 API Key。当前本地实现的确定性夹具已覆盖完整、空、部分失败、限流、鉴权失败、字段漂移、已删除密钥余量和对账异常；真实登录态 HTTP 200 与账单数值仍需在 AIHub 页面由用户验收。

升级时，AIHub 旧模型短名会与对应的保持、回滚观察和临时隔离记录一起转换为完整模型名；不会切换用户选择的模型或清空保护记录。此迁移仅作用于 AIHub 的独立存储。
