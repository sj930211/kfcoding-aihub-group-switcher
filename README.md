# KFCoding / AIHub 智能低倍率分组切换

油猴脚本支持 `kfcoding.codes` 和 `aihub.top`，会读取当前站点的分组倍率、账号可选范围和性能监测数据，把选中的一个或多个 API 密钥切换到满足可用性阈值的最低倍率分组。

## 安装

1. 在浏览器安装 Tampermonkey。
2. 点击[安装脚本](https://raw.githubusercontent.com/sj930211/kfcoding-aihub-group-switcher/main/kfcoding-group-switcher.user.js)，由 Tampermonkey 确认安装。
3. 登录 `https://kfcoding.codes/` 或 `https://aihub.top/usage`，页面右下角会出现对应站点的分组监控。
4. 从下拉选择器中勾选一个或多个 API 密钥。KFCoding 还需要选择目标模型；AIHub 使用站点公共渠道监测，不提供模型选择。
5. 按需设置分组白名单或黑名单，调整阈值后开启 `自动切换`。所有设置在变更后会自动保存。

面板顶部会显示当前脚本版本，并提供`系统 / 浅色 / 深色`皮肤选择。默认跟随操作系统；操作系统切换外观时面板会立即同步，也可以为两个站点分别固定浅色或深色。

脚本会通过 `@updateURL` 接收 GitHub 上的新版本。更新检查使用独立定时器，不依赖自动切换开关：脚本启动时会静默检查一次，之后每 5 分钟检查一次；发现新版本后标题栏图标会出现提示点。需要立即确认时，可以点击该更新图标，或从 Tampermonkey 菜单选择`检查脚本更新`；再次点击提示点会打开 Tampermonkey 安装页供用户确认升级。更新检查失败不会阻断分组监控或自动切换，也不会上传任何 API 密钥或账号数据。

面板会展示当前账号余额、本日消费、请求次数和 Token 总量，并在启动和每次分组检查时更新。KFCoding 余额使用站点的配额货币换算设置，AIHub 余额读取当前账号余额；Token 达到百万后使用 `M`，达到一亿后使用“亿”，悬停可查看精确数值。分组状态将首字延迟、完整输出耗时和缓存命中率分列展示。KFCoding 直接使用性能接口的平均首字延迟与平均完整输出耗时；AIHub 的完整输出耗时按输出 Token 数除以 Token/s 计算，悬停可查看原始数据。AIHub 直接展示公共监测的缓存命中率；KFCoding 当前分组性能接口未提供该指标，因此显示 `-`。缓存命中率不作为可用性的硬门槛，但会参与稳定优先和均衡推荐的排序；缺失时按中性值处理。`立即检查`始终先刷新余额与今日用量，并同时刷新 API 密钥列表、模型和分组状态；即使尚未选择模型或 API 密钥，余额与今日用量也会更新。AIHub 即使未选择 API 密钥也会显示分组状态。`切到策略推荐`会实时检查全部已选密钥，并按照当前策略切换；它忽略自动开关、连续确认次数和切换冷却，但仍遵守当前生效的分组名单、倍率上限和健康门槛。

分组过滤使用互斥的`白名单 / 黑名单`模式下拉和分组多选下拉。两种模式分别保存自己的名单，切换模式不会覆盖另一份；任何时刻只应用当前模式。白名单非空时只允许名单内分组，黑名单非空时排除名单内分组；当前名单留空表示不限制。旧版共用输入框的数据会按升级前启用的模式迁移到对应名单，更早版本的“允许分组”会迁移到白名单。

检查完成后，点击与`自动切换`并列的`手动切换`，弹窗会开放本次检查得到的全部分组，并在每个选项后显示倍率和完整状态。人工选择可以覆盖黑白名单、倍率上限和性能门槛，脚本会重新获取分组与密钥状态后尝试逐个切换；账号无权选择的分组仍可能被站点接口拒绝，并会记录到密钥结果和事件中。已经处于目标分组的密钥不会重复提交修改请求。

分组选择提供三种模式：`省钱优先`先按倍率排序，健康分用于同倍率决胜；`稳定优先`综合近期成功率、整体成功率、首字延迟、完整输出耗时和缓存命中率；`均衡推荐`按健康分 70% 与相对价格 30% 综合排序。所有模式都只从满足当前自动判定门槛的分组中推荐，切换确认、冷却和回滚保护保持不变。

消费保护可以设置每日消费上限。保护计数达到 80% 时显示橙色并通知一次，达到 100% 时显示红色并再次通知；它只负责提醒，不会暂停自动切换、阻止立即检查或修改任何任务。点击重置会把站点当前返回的今日消费记录为新基线，之后只统计新增消费；本地日期变化时基线和通知状态会自动归零，供应商账单本身不会被修改。

每次成功切换后，脚本默认继续观察目标分组 2 次。观察期间不会继续追逐其他推荐分组；如果目标分组的近期成功率、总成功率、指标时效、首字延迟或输出耗时不再满足条件，会优先回到切换前的分组。原分组也不可用时，按当前策略改用其他可用分组。发生健康故障的目标分组会按当前模型临时拉黑 60 分钟，避免多个密钥或后续轮询立即切回；分组状态列表会显示“临时拉黑”，事件中会记录回滚。高级参数可以调整观察次数和拉黑时间，将观察次数设为 `0` 可关闭自动回滚。旧版本的“最大延迟”会自动迁移为最大首字延迟；旧版按秒/Token 保存的输出延迟阈值不会套用到新版完整输出耗时，避免单位变化造成误判。

脚本只保存所选 API 密钥的内部 ID 列表，不保存或显示完整密钥。旧版 KFCoding 单密钥配置会自动迁移。两个站点分别保存配置、日志、拖动位置和冷却记录，互不覆盖。

面板事件会持久保存最近 10 条，刷新页面或重新打开浏览器后仍可查看；新增事件会自动淘汰最早的记录。

收起后的 `KF` 或 `AH` 按钮可以直接拖动，展开后的面板可以按住标题栏拖动。按钮和面板的位置分别保存，刷新页面后仍会恢复；窗口尺寸变化时会自动调整，避免控件停留在屏幕外。

读取接口单次超时为 25 秒，遇到超时、网络错误、限流或临时服务端错误时最多请求 3 次。同一路径的并发读取会自动合并。修改 API 密钥的请求不会自动重试，避免重复提交。

## 默认判定

候选分组必须同时满足：

- KFCoding 的目标模型已启用该分组；AIHub 的公共监测包含该分组。
- 当前账号可以为 API 密钥选择该分组。
- 分组倍率可确定。
- 分组倍率不超过配置的最大倍率；默认 `0` 表示不限制。
- 24 小时总成功率不低于 95%。
- 最近一次监测成功率不低于 95%；只判断时间最新的数据点，更早的异常柱不影响当前判定。
- 最新指标不超过 180 分钟，首字延迟不超过 120 秒；完整输出耗时默认不限制。

满足条件后按当前选择模式排序，升级后的默认模式为`省钱优先`，保持旧版按倍率选择的行为。每个密钥独立计算连续确认、切换观察和切换冷却：目标分组需要连续确认 2 次并遵守 10 分钟冷却；切换后默认观察 2 次，健康故障分组默认拉黑 60 分钟；某个密钥的当前分组失效时，该密钥不等待冷却，立即回退到可用分组。单个密钥读取、校验、切换或回滚失败不会阻断其他已选密钥。

最大倍率会约束自动切换和`切到策略推荐`。超过上限的分组会标记原因，但仍可在手动切换中由用户明确选择。

## 运行限制

- 油猴脚本只有在对应站点至少有一个页面打开时运行。后台标签页可能被浏览器节流，30 秒轮询不等于严格的实时任务调度。
- 可用性来自供应商公开的历史性能指标，能降低切到故障分组的概率，但无法保证下一次请求一定成功。
- 自动回滚同样依据供应商的分组监控数据，不会使用 API 密钥主动发送可能产生费用的模型请求，因此无法捕获监控尚未反映的单次业务请求失败。
- 如果所有候选都不满足阈值，脚本保持现有分组不变并显示原因。
- 今日用量按浏览器所在时区的本地自然日统计；KFCoding 使用站点公开的配额换算设置展示消费金额。

### AIHub 说明

- 倍率优先采用当前账号的分组倍率，其次使用可选分组倍率和公共监测倍率。
- 可用性读取 `/api/v1/public/monitor/summary` 和 `/api/v1/public/monitor/series/{range}`，近期状态只采用时间最新的一个监测点。
- 缓存命中率读取公共监测的 `cacheHitRate`；完整输出耗时使用 `outputTokens / outputTokensPerSecond` 计算。
- AIHub 公共监测没有模型字段，因此只能判断分组级可用性，不能声称某个指定模型一定可用。
- 密钥分组更新沿用站点前端接口，只提交 `group_id`，成功后重新读取密钥详情确认结果。
