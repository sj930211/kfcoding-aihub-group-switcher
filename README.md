# KFCoding / AIHub / ooioo / FluxionAI 智能低倍率分组切换

油猴脚本支持 `kfcoding.codes`、`aihub.top`、`ooioo.work` 和 `fluxionai.space`，会读取当前站点的分组倍率、账号可选范围和性能监测数据，把选中的一个或多个 API 密钥切换到满足可用性阈值的低倍率分组。

## 安装

1. 在浏览器安装 Tampermonkey。
2. 点击[安装脚本](https://raw.githubusercontent.com/sj930211/kfcoding-aihub-group-switcher/main/kfcoding-group-switcher.user.js)，由 Tampermonkey 确认安装。
3. 登录 `https://kfcoding.codes/`、`https://aihub.top/usage`、`https://ooioo.work/` 或 `https://fluxionai.space/`，页面右下角会出现对应站点的分组监控。
4. 从下拉选择器中勾选一个或多个 API 密钥，并选择目标模型。AIHub 的模型下拉来自站点公共监测当前返回的 Sol、Terra、Luna 模型状态。
5. 按需设置分组白名单或黑名单，调整阈值后开启 `自动切换`。所有设置在变更后会自动保存。

面板采用统一窄版的运维控制台布局，并划分为`监控 / 诊断 / 设置`三个内部工作区：监控页集中显示当前路由、今日用量、常用操作和分组状态；诊断页保留逐密钥结果和最近事件；设置页集中管理自动切换策略、保护参数、脚本更新及`跟随系统 / 浅色 / 深色`主题。毛玻璃透明度可在设置页通过滑杆实时调整并自动保存。所有设置修改都会自动保存。界面也支持键盘方向键切换工作区，以及降低动态效果、降低透明度和高对比度等系统辅助偏好。

脚本会通过 `@updateURL` 接收 GitHub 上的新版本。更新检查使用独立定时器，不依赖自动切换开关：脚本启动时会静默检查一次，之后每 5 分钟检查一次。发现新版本后会发送一次油猴通知，在顶部版本号旁显示 `NEW`，并在设置页提供更新按钮；同一版本不会因刷新页面或同时打开两个供应商网站而重复通知。需要立即确认时，可以在设置页底部点击`检查更新`，或从 Tampermonkey 菜单选择`检查脚本更新`。更新检查失败不会阻断分组监控或自动切换，也不会上传任何 API 密钥或账号数据。

面板会展示当前账号余额、本日消费、请求次数和 Token 总量，并在启动和每次分组检查时更新。KFCoding 与 ooioo 余额使用各自站点的配额货币换算设置，AIHub 与 FluxionAI 读取当前账号余额；Token 达到百万后使用 `M`，达到一亿后使用“亿”，悬停可查看精确数值。分组列表的倍率列同时显示标称倍率和 `≈` 开头的实际倍率；只有 AIHub 已确认缓存计费口径的候选会计算实际倍率，其他站点或计费模型缺失时显示 `≈-`。分组状态还会展示首字延迟、完整输出耗时和缓存命中率。KFCoding 与 ooioo 直接使用性能接口的平均首字延迟与平均完整输出耗时；AIHub 的完整输出耗时按输出 Token 数除以 Token/s 计算；FluxionAI 将渠道监控中的“对话延迟”作为完整输出耗时。FluxionAI 当前未提供首字延迟和缓存命中率，因此对应列显示 `-`，也不会把缺失的首字延迟当作硬性失败。缓存命中率不作为可用性的硬门槛；它会参与稳定优先和均衡推荐的健康评分。AIHub 的省钱优先使用其渠道状态页缓存基线算法：`实际倍率 = 标称倍率 × 当前缓存成本 ÷ 基线缓存成本`。缓存基线为 `97%`，缓存命中按 `$0.5/M`、未命中按 `$5/M` 计算，因此基线缓存成本为 `$0.635/M`。缓存命中率低于 97% 时实际倍率高于标称倍率，高于 97% 时才可能低于标称倍率；其他站点未公开相同基线和价格时按标称倍率排序，最终仍以账单明细为准。`立即检查`始终先刷新余额与今日用量，并同时刷新 API 密钥列表、模型和分组状态；即使尚未选择模型或 API 密钥，余额与今日用量也会更新。AIHub 和 FluxionAI 的普通立即检查不要求先选择 API 密钥，但都需要选择目标模型。`切到策略推荐`会实时检查全部已选密钥，并按照当前策略切换；它忽略自动开关、连续确认次数和切换冷却，但仍遵守当前生效的分组名单、倍率上限、目标模型状态和健康门槛。

分组过滤使用互斥的`白名单 / 黑名单`模式下拉和分组多选下拉。两种模式分别保存自己的名单，切换模式不会覆盖另一份；任何时刻只应用当前模式。白名单非空时只允许名单内分组，黑名单非空时排除名单内分组；当前名单留空表示不限制。旧版共用输入框的数据会按升级前启用的模式迁移到对应名单，更早版本的“允许分组”会迁移到白名单。

检查完成后，点击与`自动切换`并列的`手动切换`，弹窗会开放本次检查得到的全部分组，并在每个选项后显示倍率和完整状态。人工选择可以覆盖黑白名单、倍率上限和性能门槛，脚本会重新获取分组与密钥状态后尝试逐个切换；账号无权选择的分组仍可能被站点接口拒绝，并会记录到密钥结果和事件中。已经处于目标分组的密钥不会重复提交修改请求。

分组选择提供三种模式：`省钱优先`在 AIHub 按实际倍率从低到高排序，其他站点没有已确认缓存计费模型时按标称倍率排序。`稳定优先`综合近期成功率、整体成功率、首字延迟、完整输出耗时和缓存命中率；`均衡推荐`按健康分 70% 与相对价格 30% 综合排序。所有模式都只从满足当前自动判定门槛的分组中推荐，切换确认、冷却和回滚保护保持不变。

消费保护可以设置每日消费上限。保护计数达到 80% 时显示橙色并通知一次，达到 100% 时显示红色并再次通知；它只负责提醒，不会暂停自动切换、阻止立即检查或修改任何任务。点击重置会把站点当前返回的今日消费记录为新基线，之后只统计新增消费；本地日期变化时基线和通知状态会自动归零，供应商账单本身不会被修改。

每次成功切换后，脚本默认继续观察目标分组 2 次。观察期间不会继续追逐其他推荐分组；如果目标分组的近期成功率、总成功率、指标时效、首字延迟或输出耗时不再满足条件，会优先回到切换前的分组。原分组也不可用时，按当前策略改用其他可用分组。发生健康故障的目标分组会按当前模型临时拉黑 60 分钟，避免多个密钥或后续轮询立即切回；分组状态列表会显示“临时拉黑”，事件中会记录回滚。高级参数可以调整观察次数和拉黑时间，将观察次数设为 `0` 可关闭自动回滚。旧版本的“最大延迟”会自动迁移为最大首字延迟；旧版按秒/Token 保存的输出延迟阈值不会套用到新版完整输出耗时，避免单位变化造成误判。

脚本只保存所选 API 密钥的内部 ID 列表，不保存或显示完整密钥。旧版 KFCoding 单密钥配置会自动迁移。四个站点分别保存配置、日志、拖动位置和冷却记录，互不覆盖。

KFCoding 和 ooioo 的新版账户接口使用短期 access token。脚本会通过当前站点的 HttpOnly 登录会话在运行内存中获取并刷新 token，遇到 401 时只刷新并重试一次；token 不会写入油猴存储、`localStorage` 或事件日志。会话失效时，面板会明确提示对应站点需要重新登录。

AIHub 和 FluxionAI 复用页面当前的 Bearer 登录状态。脚本每次请求只读取站点当前 token，不会把 access token、refresh token 或完整 API 密钥复制到油猴存储和事件日志；登录状态失效时需要先在对应站点重新登录。

面板事件会持久保存最近 10 条，刷新页面或重新打开浏览器后仍可查看；新增事件会自动淘汰最早的记录。

收起后的 `KF`、`AH`、`OO` 或 `FX` 按钮可以直接拖动，展开后的面板可以按住标题栏拖动。按钮和面板的位置分别保存，刷新页面后仍会恢复；窗口尺寸变化时会自动调整，避免控件停留在屏幕外。

读取接口单次超时为 25 秒，遇到超时、网络错误、限流或临时服务端错误时最多请求 3 次。同一路径的并发读取会自动合并。修改 API 密钥的请求不会自动重试，避免重复提交。

## 默认判定

候选分组必须同时满足：

- KFCoding 或 ooioo 的目标模型已启用该分组；AIHub 的公共监测包含该分组且 `model_health` 明确标记目标模型为 `healthy`；FluxionAI 的可选分组支持目标模型，并且能匹配到该模型的渠道监控。
- 当前账号可以为 API 密钥选择该分组。
- 分组倍率可确定。
- 分组倍率不超过配置的最大倍率；默认 `0` 表示不限制。
- 总成功率不低于 95%。KFCoding 与 ooioo 使用所选监测窗口，AIHub 使用公共监测窗口，FluxionAI 使用站点提供的 7 天可用率。
- 最近一次监测成功率不低于 95%；只判断时间最新的数据点，更早的异常柱不影响当前判定。
- 最新指标不超过 180 分钟；站点提供首字延迟时默认不得超过 120 秒，完整输出耗时默认不限制。FluxionAI 未提供首字延迟，因此只展示和判断其对话总延迟。

满足条件后按当前选择模式排序，升级后的默认模式为`省钱优先`；AIHub 候选按 97% 缓存基线换算实际倍率，其他站点未确认相同缓存计费模型时保持按标称倍率选择。该换算只复现 AIHub 渠道状态页的口径，不替代供应商账单。每个密钥独立计算连续确认、切换观察和切换冷却：目标分组需要连续确认 2 次并遵守 10 分钟冷却；切换后默认观察 2 次，健康故障分组默认拉黑 60 分钟；某个密钥的当前分组失效时，该密钥不等待冷却，立即回退到可用分组。单个密钥读取、校验、切换或回滚失败不会阻断其他已选密钥。

最大倍率会约束自动切换和`切到策略推荐`。超过上限的分组会标记原因，但仍可在手动切换中由用户明确选择。

## 运行限制

- 油猴脚本只有在对应站点至少有一个页面打开时运行。后台标签页可能被浏览器节流，30 秒轮询不等于严格的实时任务调度。
- 可用性来自供应商公开的历史性能指标，能降低切到故障分组的概率，但无法保证下一次请求一定成功。
- 自动回滚同样依据供应商的分组监控数据，不会使用 API 密钥主动发送可能产生费用的模型请求，因此无法捕获监控尚未反映的单次业务请求失败。
- 如果所有候选都不满足阈值，脚本保持现有分组不变并显示原因。
- 今日用量按浏览器所在时区的本地自然日统计；KFCoding 与 ooioo 使用各自站点公开的配额换算设置展示消费金额，AIHub 与 FluxionAI 使用站点返回的实际消费金额。

### ooioo 说明

- 模型、分组倍率和模型可用分组读取 `/api/pricing`；整体和近期性能读取 `/api/perf-metrics`，近期状态只使用时间最新的数据点。
- 当前账号可选分组、API 密钥列表/详情、本日用量和余额分别读取 `/api/user/self/groups`、`/api/token/`、`/api/data/self` 与 `/api/user/self`。
- 密钥更新沿用站点前端的 `PUT /api/token/` 负载，并在更新后重新读取详情确认分组。修改请求不会自动重试。
- ooioo 使用独立的 `ooioo-group-switcher` 存储前缀，不会继承或覆盖 KFCoding、AIHub 的密钥选择、黑白名单、冷却或故障隔离状态。

### FluxionAI 说明

- 账号余额、API 密钥、可选分组、账号倍率和今日用量分别读取 `/api/v1/auth/me`、`/api/v1/keys`、`/api/v1/groups/available`、`/api/v1/groups/rates` 与 `/api/v1/usage/stats`。
- 可用性读取 `/api/v1/channel-monitors`。整体成功率使用站点返回的 `availability_7d`，近期状态只采用 `checked_at` 时间最新的一个监测点，不依赖数组原始顺序。
- 站点监控名称与实际可选分组名称并不完全相同。脚本会同时核对目标模型、平台和标准化分组名；无法可靠匹配的分组标记为“无性能数据”，不会参与自动切换。
- 模型下拉只展示同时存在可选分组和渠道监测的模型。未被站点监测的模型不会借用同分组其他模型的状态来声称可用。
- 倍率优先采用账号专属倍率，其次采用当前有效的促销倍率，再回退到基础倍率；处于站点配置的高峰时段时会叠加高峰倍率。
- FluxionAI 当前渠道监控提供对话总延迟和端点 PING，但未提供首字延迟、输出 Token/s 或缓存命中率。脚本把对话总延迟显示为完整输出耗时，其余缺失指标显示 `-`。
- 密钥更新沿用站点前端的 `PUT /api/v1/keys/{id}`，只提交 `group_id`，成功后重新读取密钥详情确认结果。修改请求不会自动重试。
- FluxionAI 使用独立的 `fluxionai-group-switcher` 存储前缀，不会继承或覆盖其他三个站点的密钥选择、黑白名单、冷却或故障隔离状态。

### AIHub 说明

- 倍率优先采用当前账号的分组倍率，其次使用可选分组倍率和公共监测倍率。
- 可用性优先读取 `/api/v1/public/providers` 和 `/api/v1/public/providers/series`，并使用站点返回的供应商、分组倍率、`model_health`、`model_detection` 与最新监测点；新接口不可用时回退到 `/api/v1/public/monitor/summary` 和 `/api/v1/public/monitor/series/{range}`。近期状态只采用时间最新的一个监测点；仅当分组的 `probe_model` 与目标模型相同时才使用该柱状图，否则使用目标模型自己的 `model_health`，避免 Luna 等其他模型的故障误判 Sol。序列接口临时返回非 JSON 数据时会降级使用汇总接口中的最新状态，不中断本次分组检查。
- 缓存命中率读取公共监测的 `cacheHitRate`；完整输出耗时使用 `outputTokens / outputTokensPerSecond` 计算。
- 模型下拉从公共监测的 `model_health` 键生成，当前站点返回 Sol、Terra、Luna。目标模型状态为 `healthy` 时允许继续判定，`failed` 显示“目标模型不可用”；当前接口返回 `stale` 时，只有存在适用于同一目标模型的 `model_detection` 记录才不再误判为“模型状态未知”，字段缺失、检测不适用或检测指向其他模型时仍禁止自动切换。`suspected`、`insufficient_evidence`、`detection_failed`、未完成、过期或未知等检测状态继续显示为“检测警告”，不单独阻止自动切换、触发回滚或加入故障隔离；分组仍须满足最新可用状态和其他自动判定门槛。
- 密钥分组更新沿用站点前端接口，只提交 `group_id`，成功后重新读取密钥详情确认结果。
